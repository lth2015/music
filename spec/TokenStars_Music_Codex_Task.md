# TokenStars 音乐平台：任务综述与验收标准

版本：v0.1 · 2026-09-09  
产品工作名：LOOPSCENE，正式名称待确认。  
用途：作为 Codex 项目的实施任务文件，可放入仓库根目录，建议命名为 `PROJECT_TASK.md`。

> 本任务要求实现可运行、可测试、可交接的产品。下面的首发范围与价格是当前实施基线；音乐供应商、真实合同及正式收费上线仍需外部条件落实。模拟运行成功、技术验收通过、商业验证成立，必须分别报告。

## 1. 任务综述

为日本的个人短视频创作者开发一个时尚、易用的 AI 配乐 Web 平台。用户选择场景、描述情绪，生成一份 30 秒纯音乐，试听后裁剪、下载，并查看该音源的使用条件记录。

业务上复用 TokenStars 的文本模型接入与成本管理能力，但音乐产品独立计量、独立核算。GPT 通过 TokenStars 理解需求、整理参数；音乐波形由另行获得平台经营授权的音乐模型供应商生成。

本轮需要交付：前后端、异步生成、次数账本、支付与订阅、私有作品库、基础运营后台、测试、本地运行方式、AWS 部署配置，以及如实填写的验收报告。

本文的 UI / GEN / PAY / AI / SEC 编号项均属于 MVP 的 P0 验收范围；依赖真实外部环境的部分可以暂记待验证，但不能视为已通过。配套背景文件为 `TokenStars_Music_Product_Design_v0_1.docx`；本文件足以开始开发，不要求把 Word 作为运行依赖。

### 1.1 已确定的实施基线

| 项目 | 实施要求 |
| --- | --- |
| 用户 | 日本居住、18 岁以上个人创作者；招募重点为年轻短视频发布者 |
| 首发内容 | 30 秒无歌词、无人声的纯音乐配乐 |
| 首发场景 | 夜景与生活记录优先；穿搭、游戏剪辑作为其他场景模板 |
| 产品形态 | 日文响应式 Web，移动优先，桌面可用 |
| 收费模式 | 先按需购买，验证复购后增加有限额度月订阅 |
| 单次包 | DROP：980 日元含税，5 次生成，拟定购买后 90 天有效，无自动续费 |
| 月订阅 | CREATOR：1,980 日元含税，每个账期 20 次，未用次数不结转 |
| 计量单位 | 1 次额度对应 1 份技术上成功交付的 30 秒音源 |
| 文本模型 | GPT 优先，经 TokenStars 调用；不得静默绕过 TokenStars 直连其他采购渠道 |
| 音乐模型 | 独立供应商适配层；真实供应商与获准用途尚未确定 |
| 云基础 | AWS 东京区域：EKS / RDS PostgreSQL / ALB / S3；补充 SQS、CloudFront、Cognito 等必要服务 |
| 支付 | Stripe 信用卡支付与 Billing；公司销售自己的服务，不做音乐人分账 |

价格、额度、有效期必须由服务端版本化配置。正式销售前按已签授权、实际报价和法律审查重新确认，不能把设计假设直接视为生效合同。

### 1.2 本轮不纳入的能力

- 歌词、人声、歌手声音模仿、翻唱、参考音乐或哼唱上传。
- Spotify 等音乐发行、版税分账、Content ID 登记、音乐交易市场。
- 公开作品社区、关注关系、排行榜、他人作品 Remix。
- 年付、不限量套餐、自动充值、可转让或提现的次数余额。
- 原生 iOS / Android App、视频上传与云端视频合成、自训练模型和 GPU 集群。

以上能力不能通过隐藏入口或供应商的默认选项意外开放。

## 3. 运行模式与外部依赖

### 3.1 三种模式

| 模式 | 身份、音频与支付 | 必须满足的边界 |
| --- | --- | --- |
| `demo` | 本地演示身份、自有测试音频、模拟支付 | 开发环境专用，界面持续标明演示；没有真实扣款，也不签发商用使用承诺 |
| `integration` | Cognito / TokenStars / 获准音乐 API 按可用条件接入；Stripe test mode | 逐个记录真实与模拟的依赖；不得将局部模拟的结果报告为全链路真实验证 |
| `production` | 正式身份、获准音乐服务、真实支付与受控云资源 | 禁止开发身份、模拟支付及假音频适配器；缺少必要配置时启动失败或关闭相应收费功能 |

不要使用一组模糊的布尔值使运行模式互相矛盾。启动时校验模式、身份、支付、存储及供应商配置的合法组合。

### 3.2 需要接入的配置

提供 `.env.example`，只放变量名、说明与非敏感示例值；真实密钥不得写入仓库。

- TokenStars：base URL、API key、实际可用模型 ID、超时、并发与成本配置。
- 音乐供应商：provider ID、端点、密钥、模型版本、能力、合同版本、计费规则、回调或查询方式。
- Stripe：模式、secret key、Webhook secret、版本化 price ID；前端只取得允许公开的配置。
- AWS：region、数据库连接、S3 bucket、SQS queue、Cognito user pool / app client 等。
- 运营：单用户并发限制、全局日预算、试用开关、订阅开关、授权启用状态。

不得编造 TokenStars 的端点路径、模型 ID、结构化输出支持、价格或 SLA。未获得接口资料时保留清楚的适配边界与待确认项。

## 4. 技术架构与工程结构

### 4.1 建议技术方案

新仓库采用 TypeScript 工程，前端 React，API 使用 Fastify 模块化单体，Worker 为独立进程。若已有成熟技术栈，先保留合理部分，不为统一形式重写。运行时和依赖选择实施时仍受支持的版本并锁定，不使用浮动版本代替可复现构建。

| 位置 | 职责 |
| --- | --- |
| `apps/web` | 日文界面、播放器、表单、作品与账单页面 |
| `apps/api` | 认证、项目、任务、权益、订单、许可、运营 API |
| `apps/worker` | Outbox 派发、供应商请求、状态查询、音频处理、事件消费 |
| `packages/contracts` | 请求响应类型、Schema、错误码、业务枚举 |
| `packages/providers` | TokenStars、音乐、存储与队列适配器 |
| `packages/db` | 数据模型、迁移、事务与仓储 |
| `packages/ui` | 复用组件与视觉变量，按实际规模拆分 |
| `infra/terraform`、`infra/helm` | 云资源与应用部署配置 |
| `docs`、`tests` | 架构、运行手册、验收证据和测试 |

### 4.2 运行关系

1. Web 静态资源通过 S3 / CloudFront 交付；API 经 ALB 进入 EKS。
2. API 在同一个 RDS 事务中创建任务、预留次数并写 Outbox。
3. Outbox 派发至 SQS；Worker 认领任务并执行 GPT 参数整理与音乐生成。
4. 原始、隔离及导出音源存入不同访问边界的私有 S3；状态、成本及使用条件记录写回 RDS。
5. Web 使用有退避和上限的状态轮询恢复任务，不保持一个等待音频完成的长 HTTP 请求。
6. Stripe Webhook 验签后可靠入库，异步处理订单、订阅和权益；浏览器跳转不作为付款证据。

生产 API / Worker 在私有子网，API 至少两个副本跨两个可用区，RDS 使用 Multi-AZ。凭证使用 Secrets Manager 与工作负载身份，浏览器不得持有服务端密钥。

本地可以用 PostgreSQL 容器、文件存储和可恢复的本地队列适配器替代 AWS 服务；必须保持相同接口及任务、账本语义。本地适配器通过测试不代表真实 S3 / SQS 已验证。若环境不能启动容器，说明可连接的 PostgreSQL 方式，不能用内存余额冒充数据库事务验收。

## 6. 生成任务与次数账本验收

### 6.1 状态与扣费规则

| 状态 | 含义 | 次数处理 |
| --- | --- | --- |
| `VALIDATING` | 检查身份、输入、用途与服务可用性 | 不消费 |
| `RESERVED` | 事务创建任务并预留额度 | 预留 1 次 |
| `QUEUED` | 已等待 Worker 处理 | 保持预留 |
| `SUBMITTED` | 已取得供应商接单依据 | 不重复提交、不重复扣费 |
| `UNKNOWN` | 请求可能已被上游接收，结果尚不可确认 | 保持核实，禁止盲目重复收费请求 |
| `PROCESSING` | 校验、隔离、处理输出与检查用途 | 不重复扣费 |
| `DELIVERED` | 音源及使用条件记录已可访问 | 预留转为消费一次 |
| `FAILED` / `REJECTED` | 终局失败或不能交付 | 释放预留；误消费通过补偿流水修正 |
| `CANCELLED` | 尚未提交供应商的任务被成功取消 | 释放预留；与 Worker 认领须防竞争 |

付款购买的是服务次数。主观不喜欢不属于技术失败；主动重生需要新次数。技术失败、供应商拒绝和输出审核不通过不消耗用户次数。不得将“一次生成”默认实现成上游多份付费结果。

### 6.2 必须通过的关键场景

| 编号 | 操作 / 故障 | 预期结果 |
| --- | --- | --- |
| GEN-01 | 同一幂等键连续或并发提交相同请求 | 返回同一任务；只有一次有效预留和至多一次对应上游提交 |
| GEN-02 | 同一幂等键提交不同内容 | 返回冲突；不覆盖原任务、不额外扣费 |
| GEN-03 | 账户剩余 1 次，两个不同任务并发抢占 | 仅一个成功预留；另一请求明确余额不足；余额不为负 |
| GEN-04 | Outbox 派发失败或 SQS 重复投递 | 任务最终可恢复；消费和上游提交不因重复消息重复发生 |
| GEN-05 | Worker 在网络调用期间退出 | 通过状态、租约或版本控制恢复；不长期持有数据库事务，不自动再次调用可能已接单的上游 |
| GEN-06 | 供应商接单后本地超时 | 进入核实；优先按原请求查询或使用已确认的幂等机制；没有证据时不盲重试 |
| GEN-07 | 技术失败、损坏音频、无意人声或输出被拒绝 | 不进入可下载状态；释放或补偿次数一次；记录实际已经发生的上游成本 |
| GEN-08 | 任务完成后重复收到成功回调 | 状态和消费保持不变；不产生第二份消费流水 |
| GEN-09 | 已补偿用户后上游迟到成功 | 不再次扣次数；记录迟到结果和平台承担的成本，按明确策略处理该音源 |
| GEN-10 | 用户刷新、关页或重新登录 | 从持久化状态恢复任务；不重新生成、不丢历史订单 |
| GEN-11 | 有效期内提交，处理期间次数批次到期 | 成功任务可交付；失败按配置的补偿政策处理，不静默丢失预留；过期补偿规则须在收费前确定 |
| GEN-12 | 用户取消与 Worker 同时准备提交 | 只出现取消成功或已提交继续处理之一；不能既宣称取消成功又再次扣次数 |

账本按批次维护来源、授予数量、预留、消费、释放、撤销、有效期和补偿记录。默认先用即将到期的可用批次，未到期不足时不能借用未来账期额度。

使用追加式流水和数据库唯一约束，并提供可对账的余额查询。每日检查订单、权益与任务的一致性；运营调整必须保留操作者与理由，不能直接覆盖一个 `credits` 数字。

## 7. Stripe 支付、订阅与退款验收

| 编号 | 场景 | 验收要求 |
| --- | --- | --- |
| PAY-01 | 创建支付订单 | 金额、币种、price ID 与产品规则由服务端决定；篡改前端金额不能改变订单 |
| PAY-02 | 浏览器回到成功页 | 只查询后台订单；未验证付款时显示确认中，不发放次数 |
| PAY-03 | 单次包真实测试付款成功 | 核对订单、金额、币种和成功状态；只授予一个 5 次批次 |
| PAY-04 | Webhook 验签 | 使用原始请求体与专属密钥；伪造、过期或不合法签名不改变订单、权益 |
| PAY-05 | 重复 / 乱序事件 | event ID 与业务对象双重幂等；必要时查询 Stripe 当前对象；不重复发放、不用旧状态覆盖新状态 |
| PAY-06 | 订阅本期付款成功 | 以正确账期的已付款账单授予本期 20 次；不用多个事件重复发放；本轮关闭升级、按比例变更和试用订阅等额外计费分支 |
| PAY-07 | 续费失败 / 需要验证 | 不发新周期额度；保留已有合法权益；提示更新付款方式；恢复收款后正确授予一次 |
| PAY-08 | 取消订阅 | 在服务端设置期末停止续费；现有服务保留到准确账期结束；不产生下一期扣款；失败不显示成功 |
| PAY-09 | 退款与拒付 | 退款幂等；按订单和批次核算未用、预留和已履约部分；与生成中的任务协调，不出现负余额或重复撤销 |
| PAY-10 | 停订后访问历史音源 | 根据生成时已获得并继续有效的使用权处理，不单凭“当前无订阅”撤回历史授权；真实合同不支持时不得提前承诺 |
| PAY-11 | 凭证与商户结算 | 保存付款、手续费、退款、净额及 payout 关联；可对账，已收费但未发权益的订单可恢复处理 |
| PAY-12 | 信用卡与 3DS | 卡片输入交给 Stripe 托管流程；不存卡号与 CVC；在 test mode 覆盖成功、失败、需验证和返回中断 |

订阅功能应开发和测试完整，但对外开关默认关闭，待复购验证后开放。免费生成默认关闭；若启用，最多 2 次、限制滥用并计入成本，真实上游也须允许该用途。

拟议退款规则为未消费且购买后 7 天内可申请原路退款、技术失败返还次数、误扣费纠正；退款、次数有效期和法定权利必须经审查后配置发布。Codex 不应自行把该拟议政策写成已审定法律结论。

首发拟允许个人 SNS 视频及约定的收益化用途，不默认包含品牌广告、客户交付、歌曲单独转售或素材库分发。真实允许范围必须来自已签合同。

| 编号 | 验收要求 |
| --- | --- |
| SEC-01 | 账户 A 即使知道账户 B 的任务、曲目、订单、导出或许可 ID，也不能读取或操作；不能只依赖前端隐藏按钮 |

| SEC-09 | 未获得正式授权时，真实收费和商用音源交付保持关闭；演示记录不能生成“独家版权”“零侵权保证”等承诺 |

| SEC-13 | 提供真实经营主体的特商法披露、利用条款、隐私、退款与联系入口；占位内容可用于演示，正式收费不能保留占位 |

## 10. 最小 API 与数据契约

交付 OpenAPI 或等效的可检查接口文档，包含认证、输入、输出、错误码与幂等要求。

| 接口 | 行为 |
| --- | --- |
| `POST /v1/generations` | 接收项目、场景与输入；采用统一幂等键规范；返回 `202` 和任务 ID |
| `GET /v1/jobs/:id` | 返回本人任务状态、阶段、结果或稳定错误码 |
| `GET /v1/tracks` | 按本人账户分页查询私有作品与状态 |

| `GET /v1/entitlements` | 返回可用、预留、到期批次和账期信息 |
| `POST /v1/checkout` | 根据服务端产品键创建 Stripe Session，禁止采信客户端金额 |
| `GET /v1/orders/:id` | 返回本人订单的可靠付款和权益处理状态 |

| `POST /v1/subscription/cancel` | 幂等停止未来续费，返回真实生效时间 |

## 11. 商业指标、成本与验证

### 11.1 最小事件

至少记录场景访问、样音播放、完成注册、提交生成、实际交付、导出、首笔付款、复购、续费、退款、取消与投诉。付款及生成完成以服务端事件为准，不根据浏览器点击推断成功。

事件带稳定 ID、时间、匿名化用户关联、产品及价格版本、实验版本；不把完整提示词、邮箱或银行卡信息发送到行为分析系统。测试、内部与演示事件独立标识并排除。

本任务补充以下实施口径，避免“必须付款才能生成”造成转化统计循环：

- 14 日付费转化：完成注册且观察满 14 天的合格用户中，注册后 14 天内完成首笔实际付款的比例。
- 首日激活：注册后 24 小时内成功生成、试听至少 10 秒并导出；单独标明先付费还是先试用。
- 第 7 日再次使用：首次激活后第 7 至 13 天再次成功生成的比例，只看已成熟样本。
- 首次续费：经历一个完整账期及 7 天观察窗口的首月订阅中，实际收取第二期款项的比例。
- 若启用免费生成，额外报告“付费前试用激活 → 首次付款”的转化，不能混入先付款用户。

### 11.2 成本与经营输出

后台或管理报表至少可以计算每次交付成本、每个实际采用结果成本、平均订阅贡献、满额使用贡献、退款与支付成本、供应商费用和预算消耗。采用结果与单纯下载区分；缺少真实采用数据时显示不可计算。

上游按量费、可抵扣的最低采购承诺、不可抵扣固定授权费、收入分成分开记录。最低承诺与可抵扣调用费取较大值，避免重复计算；实际合同计费基数优先。

现有测算的 45 日元请求成本、90% 技术成功率、0 收入分成等均是预算假设，不能写成供应商真实费用。核算可参考 `TokenStars_Music_Unit_Economics.xlsx`；代码中的成本模拟与真实成本必须分开。

### 11.3 商业验证不作为代码已完成的虚构成果

产品负责人执行：先访谈约 20 位目标创作者；获准后做人工辅助配乐与至少 10 位非亲友真实付费用户；再进行小规模 Web 付费和复购验证。月订阅根据重复需求开放。

平均贡献率 50%、满额贡献率 30%、首次续费率 50% 是拟议管理门槛，不是市场已验证数据。第 9 周启动月订阅时，第 12 周通常没有成熟续费结果，应延长观察而非提前宣布达标。Codex 负责记录和报表，不能用演示数据证明商业成功。
